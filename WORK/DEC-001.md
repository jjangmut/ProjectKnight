## 결정 내용

Project Knight의 게임 엔진은 Godot를 사용하고, 게임 로직의 기본 스크립트 언어는 GDScript를 사용한다.

이 결정은 Project Knight에만 적용한다. 향후 다른 게임 프로젝트의 엔진과 스크립트 언어는 각 프로젝트에서 별도로 결정한다.

## 결정 이유

1. Project Knight는 작은 규모의 2D 모바일 액션 프로토타입이다.
2. 이번 프로젝트의 핵심 목표 중 하나는 AI Agent 중심 개발 방식을 검증하는 것이다.
3. Godot의 비교적 단순한 Scene / Node / Resource 구조는 AI Agent가 프로젝트 구조를 이해하고 수정하기에 적합하다.
4. GDScript는 코드 양이 비교적 적고 Godot API와 직접 연결되어 있어 AI Agent가 빠르게 작성·수정·검증하기 좋다.
5. Godot는 무료 오픈소스 엔진이며 엔진 사용료와 매출 기반 로열티 부담이 없다.
6. 초기 프로젝트에서는 Unity 생태계의 규모보다 빠른 반복 개발과 자동화 친화성을 우선한다.

## 검토한 대안

### 대안 A — Godot + GDScript

설명: Godot의 기본 스크립트 언어를 사용해 작은 2D 프로토타입을 빠르게 반복 개발한다.

장점:

- 작은 2D 프로젝트에 적합한 단순한 구조
- Scene / Node 기반 구조가 AI Agent가 파악하기 쉬움
- GDScript 코드가 간결함
- Godot API와 자연스럽게 연결
- 무료 오픈소스
- 엔진 라이선스 비용 및 로열티 없음
- Git 기반 자동화와 소규모 프로젝트 관리에 유리

단점:

- Unity보다 상용 Asset / SDK 생태계가 작음
- 사용자의 기존 C# 경험 활용도가 낮음
- 일부 모바일 상용 SDK 연동에서 추가 작업 가능성

### 대안 B — Godot + C#

설명: Godot의 프로젝트 구조를 사용하면서 게임 로직은 C#으로 작성한다.

장점:

- Godot 구조와 C# 경험을 함께 활용 가능
- 정적 타입과 기존 C# 개발 경험 활용

단점:

- GDScript보다 프로젝트 설정과 빌드 구조가 복잡해질 수 있음
- 이번 프로젝트의 AI 중심 빠른 반복 개발 목적에는 GDScript보다 장점이 적음

### 대안 C — Unity + C#

설명: Unity 생태계와 C#을 사용해 모바일 프로토타입을 제작한다.

장점:

- 사용자의 기존 개발 경험 활용
- 모바일 상용 생태계와 SDK가 매우 풍부
- Asset 및 자료가 많음

단점:

- Project Knight 규모에는 상대적으로 무거움
- 프로젝트 구조와 메타데이터 관리 요소가 더 많음
- AI Agent 실험 측면에서는 Godot + GDScript보다 단순성이 떨어짐
- 사업 규모에 따라 라이선스 비용이 발생할 수 있음
