# [DEC-014] AI 다중 작업 환경 브랜치 및 인계 운영 정책

- 결정일: 2026-10-02
- 결정자: Studio Director / Project Manager
- 상태: DECIDED & IMPLEMENTED

## 1. 배경

Project Knight는 Codex, Antigravity, ChatGPT Chat 등 서로 다른 AI 작업 환경을 병행한다. Codex 사용량 소진이나 세션 전환 시 작업을 이어가기 위해서는 로컬 상태가 아닌 GitHub를 공통 기준으로 삼아야 하며, 동일 브랜치 직접 수정 방식은 충돌·누락·검증 혼동 위험이 있다.

## 2. 결정

표준 브랜치 구조를 다음과 같이 사용한다.

- `main`: 안정 기준선
- `integration`: 모든 AI 작업의 통합 기준선
- `codex/*`: Codex 작업
- `chatgpt/*`: ChatGPT Chat 작업
- `antigravity/*`: Antigravity 작업
- 기존 `task/*`: 과거/진행 중 기능 브랜치 보존

2026-10-02 시점의 `task/art-stage-batch-001` 최신 상태에서 `main`, `integration`을 생성한다.

## 3. 통합 규칙

1. 신규 기능/수정은 `integration`에서 전용 브랜치를 분기한다.
2. 전용 브랜치에서 직접 작업하고 커밋/push한다.
3. 전용 브랜치 완료 후 `integration` 대상으로 PR을 만든다.
4. GitHub 기반 ChatGPT가 수행한 변경은 로컬 실행 검증이 완료되기 전까지 `main`으로 승격하지 않는다.
5. Codex/Antigravity가 Godot 헤드리스 및 Android 실기 검증을 수행한 통합 상태만 `main` 승격 후보가 된다.

## 4. 인계 규칙

작업 인계의 최소 단위는 다음 3개다.

- GitHub 원격 커밋
- 최신 `STATE.md`
- 재개 가능한 다음 작업 설명

로컬 수정만 존재하는 상태는 인계 완료가 아니다.

## 5. STATE.md 필수 필드

각 인계 시 `STATE.md`에 최소 다음 정보를 유지한다.

- 기준 브랜치
- 기준/마지막 커밋
- 최근 완료 작업
- 검증 결과
- 미실행 검증
- 알려진 문제/블로커
- 다음 우선 작업
- 다음 작업의 관련 파일

## 6. 기대 효과

- Codex 토큰 소진 후 ChatGPT Chat에서 즉시 재개
- AI 에이전트 간 변경 충돌 감소
- 실제 실행 검증과 정적 분석 결과의 혼동 방지
- 안정 브랜치와 개발 통합 브랜치 분리
- 장기 프로젝트 상태 추적 가능
