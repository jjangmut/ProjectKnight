## 1. 작업 목적

현재 Project Knight의 그래픽 완성도가 상용 출시 후보 수준에 미달한다고 판단한다.

이번 작업의 목적은 Antigravity 내부에 **그래픽 품질 전담 자율 개선 에이전트(Graphics Quality Director Agent)**를 만들고, 이 에이전트가 실제 게임 화면을 반복 검증하면서 그래픽 문제를 스스로 찾고 수정하고 다시 검증하는 폐루프(Closed Loop)를 구축하는 것이다.

단순히 에셋을 추가하거나 수치를 키우는 작업이 아니다.

**실제 플레이 화면이 좋아졌는지를 기준으로 판단하고, 좋아지지 않았다면 다시 수정한다.**

## 2. 핵심 지시

Antigravity는 아래 역할을 수행하는 전담 에이전트를 생성한다.

### Agent Name
`JPStudio Graphics Quality Director`

### Mission
Project Knight의 플레이 화면을 지속적으로 캡처·검토하여 다음 항목의 품질을 상용 모바일 2D 액션 게임 수준까지 끌어올린다.

- 캐릭터 비주얼 완성도
- 적/보스 비주얼 완성도
- 배경 깊이와 공간감
- 조명/색감/대기감
- 타격 이펙트
- 스킬 이펙트
- 애니메이션 가독성
- 전투 가독성
- UI와 월드의 시각적 일관성
- 화면 전체의 아트 디렉션 통일
- 모바일 화면에서의 시인성

에이전트는 문제를 발견하면 보고만 하지 말고 직접 수정한다.

## 3. 자율 반복 루프

에이전트는 아래 사이클을 반복한다.

1. `integration` 최신 상태에서 전용 브랜치 생성
   - 예: `antigravity/graphics-quality-pass-001`
2. Godot에서 대표 플레이 구간 실행
3. 지정 캡처 포인트의 스크린샷 또는 짧은 영상 확보
4. 그래픽 평가표 기준으로 문제 목록 작성
5. 영향도가 가장 큰 3~5개 문제를 우선 수정
6. 관련 Godot Headless Smoke/회귀 테스트 실행
7. 동일 구간을 다시 캡처
8. Before / After 비교
9. 실제 개선 여부 판정
10. 개선이 부족하면 다시 수정
11. PASS 기준 충족 시 커밋 + push + STATE 갱신
12. 다음 그래픽 패스로 이동

**한 번 수정 후 종료하지 않는다.**

대표 장면마다 최소 2회 이상 Before/After 비교를 거치며, 개선 효과가 불명확하면 추가 반복한다.

## 4. 최우선 개선 순서

### P0 — 화면 전체가 프로토타입처럼 보이는 문제
먼저 아래를 제거한다.

- 임시 도형/Polygon2D가 최종 그래픽처럼 노출되는 부분
- 단색 면이 큰 비율을 차지하는 배경
- 캐릭터/보스와 배경의 스타일 불일치
- 값만 높은 HDR/Glow로 디테일 부족을 감추는 표현
- 크기만 키운 보스
- 반복되는 동일 장식/패턴
- 기계적으로 배치된 플랫폼/벽/배경 요소
- 눈에 띄는 플레이스홀더 UI

## 7. 통과 기준

개별 숫자만 올리는 방식은 금지한다.

그래픽 패스 완료 조건:

- 대표 캡처 포인트 전체에 Before / After 존재
- A~F 중 어느 항목도 평균 3 미만이면 완료 불가
- 핵심 전투 장면은 A/B/C/D/E 평균 4 이상 목표
- 공격 전조가 이펙트에 가려지지 않음
- 플레이어 캐릭터가 어떤 배경에서도 즉시 식별 가능
- Stage 1~5가 스크린샷만 보고도 서로 다른 지역으로 구분 가능
- UI가 프로토타입 도구처럼 보이지 않음
- 기존 게임 플레이/충돌/보스 진행 회귀 테스트 PASS
- 성능 저하가 확인되면 효과를 줄여 품질/성능 균형 재조정

## 8. 성능 제한

모바일 우선 프로젝트이므로 그래픽 향상으로 성능을 무시하지 않는다.

Antigravity 에이전트는 매 패스에서 최소 다음을 확인한다.

- 불필요한 매 프레임 노드 생성 여부
- 과도한 CPUParticles2D
- 지나치게 많은 Line2D / Polygon2D
- 대형 반투명 오버드로우
- 불필요하게 큰 텍스처
- 반복 생성 후 queue_free 누락
- 화면 밖 VFX 잔존

실기 FPS 측정이 가능하면:
- 평균 FPS
- 최저 FPS
- 보스전 최저 FPS

를 기록한다.

## 9. 변경 금지선

그래픽 개선 과정에서 아래를 임의로 바꾸지 않는다.

- 플레이어 핵심 조작 규칙
- 적 AI 핵심 전투 로직
- Stage 진행 조건
- 보스 HP/공격력/난이도
- Save 구조
- BM
- 충돌 판정 크기

시각과 충돌이 심하게 어긋나는 경우에만 충돌 변경을 검토하며, 이 경우 별도 QA 근거를 남긴다.

## 10. 기존 문제에 대한 특별 지시

### 보스
현재 보스는 최근 단순 scale 확대가 많이 들어갔다.

**"더 크게"는 더 이상 품질 개선으로 인정하지 않는다.**

다음 중심으로 수정한다.

- 실루엣 디테일
- 포즈
- 공격 애니메이션
- 지면 그림자
- 발광 부위
- 재질 차이
- 페이즈 변화
- 배경과 대비
- 공격 전조

### Glow/HDR
HDR 수치가 높다고 그래픽 품질이 높은 것이 아니다.

- Bloom으로 경계가 무너지는 경우 낮춘다.
- 흰색/네온색 면적을 제한한다.
- 핵심 공격/보상/보스 코어 등에만 강조를 집중한다.
- 평상시 화면과 클라이맥스 화면의 밝기 차이를 만든다.

### 절차적 도형
Polygon2D / Line2D는:
- 디버그
- 보조 VFX
- 작은 장식

에는 사용할 수 있다.

그러나 최종 캐릭터/보스/배경의 주 그래픽을 절차적 도형으로 대신하지 않는다.

## 11. 검증 명령/대상

각 패스에서 가능한 범위의 자동 테스트를 수행한다.

우선 대상:
- `campaign_transition_test.gd`
- `mobile_controls_smoke.gd`
- `campaign_full_qa.gd`
- `game_and_graphic_quality_smoke.gd`
- 그래픽 변경 파일과 직접 관련된 추가 smoke 테스트

자동화 PASS만으로 그래픽 PASS를 선언하지 않는다.

**Before/After 실제 화면 검토가 필수다.**

## 13. 종료 조건

에이전트는 단순히 "작업 완료"라고 판단하지 않는다.

다음 조건 중 하나에서만 캠페인을 종료한다.

1. 대표 장면 전체가 통과 기준 충족
2. 기술적 한계로 더 이상 개선이 불가능하고 구체적 blocker 기록
3. Studio Director가 중단 지시

그 외에는 다음 그래픽 패스를 계속한다.

## 14. 첫 실행 지시

첫 패스는 **Stage 1 Vertical Slice**로 제한한다.

범위:
1. 시작 화면
2. 일반 전투
3. 선택 루트
4. BossCommander
5. 보스 처치/보상

목표:
- 전체 화면이 현재보다 명백히 상용 게임에 가까워질 것
- 캐릭터/배경/VFX/UI 간 스타일 통일
- 과도한 Glow/도형 의존 감소
- 실제 캡처 Before/After 비교

Stage 1이 기준 품질에 도달한 후 그 스타일 시스템을 Stage 2~5로 확장한다.
