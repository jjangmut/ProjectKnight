## 결정 내용

프로토타입은 왼쪽 이동 입력과 오른쪽 공격·점프·회피 버튼을 사용한다. 회피는 각 행동을 독립적으로 검증하기 위해 별도 버튼으로 유지한다.

생존 및 재도전 구조는 다음과 같다.

- 기본 피격 허용: 3회
- 사망: 3회 피격 시
- 체크포인트: 1개
- 재시작: 빠른 재시작
- 난도 방향: 중간 난도

극단적인 고전식 고난도를 그대로 재현하지 않는다. 핵심 흐름은 **관찰 → 판단 → 이동·공격·회피 → 실패 → 학습 → 빠른 재도전**이다.

## 결정 이유

- 공격, 점프, 회피를 독립적으로 검증한다.
- 각 행동의 사용 빈도와 재미를 명확하게 평가한다.
- 최종 모바일 UI에서 버튼 수가 많다고 판단되면 후속 결정으로 간소화할 수 있다.
- 높은 처벌보다 실패 원인의 이해와 빠른 학습을 우선한다.

## 검토한 대안

### 대안 A — 독립 행동 버튼

설명: 공격, 점프, 회피를 각각 별도 버튼으로 제공한다.

장점:

- 행동별 입력과 사용 빈도를 명확하게 검증 가능
- 실패 원인과 입력 결과를 구분하기 쉬움

단점:

- 모바일 화면에서 버튼 수와 화면 가림이 늘어날 수 있음

### 대안 B — 회피 입력 간소화

설명: 이동 이중 입력 등으로 회피를 이동 조작에 결합한다.

장점:

- 화면의 행동 버튼 수를 줄일 수 있음

단점:

- 이동과 회피 입력이 혼동될 수 있고 회피 자체의 재미를 분리해 평가하기 어려움
