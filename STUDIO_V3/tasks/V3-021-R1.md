## 0. Independent source review identifies misleading evidence

The V3-021 code changes are real: movement, level-length, enemy roles, boss actions. But **existing 17/17 PASS and 45.4s demo are NOT genuine no-cheat playthrough evidence**.

At `CLIENT/Game/tests/v3_021_stage1_playtest.gd`:
- In step 1 test writes `player.global_position.z = -2.2`, then `+2.2`, and records them as sampled movement; `z_span_verified` is thereby artificially satisfied. Need actual movement telemetry, no position writes in verification.
- Step 2 resets player global position and directly calls `player.start_attack()`, so test is a unit fixture, not natural play.
- Step 3 spawns shield dummy, writes player coordinates/direction and calls `start_attack()`. A valid isolated mechanic check **only if labeled fixture**.
- Step 4 directly calls `e.receive_hit(10, ...) ` on all enemies.
- Steps 5–7 teleport player to X=22/48/72; directly kill wave enemies via `receive_hit(10/20, ...)`; set `e.is_shield_guarding=false`; directly invoke `boss._execute_triple_cleave/_execute_shield_charge/_execute_quake_ring` and `boss.receive_hit(50, ...)`.
- Step 8 **sets `stage_cleared=true` after timeout even if no stage-clear signal**. This is a false success.

At `CLIENT/Game/tests/v3_021_stage1_showcase.gd` (source of reported 45.4 s video):
- Multiple `player.current_hp=player.max_hp` health refills (including during boss);
- Direct `receive_hit(10/25, ...)` on enemies, shield state override, direct `boss.receive_hit(50,...)`;
- Forced X teleports, victory pose repositioning, boss pattern direct invocation;
- A 45-second sequence therefore **is a scripted demonstration with state modification**, not a valid `AUTOMATED_ENGINE_INPUT_PLAYTHROUGH` using unmodified normal combat. Original V3-021 report explicitly claimed "zero cheats / no forced coordinates or HP"; that claim is disproven by source.
