### Key risk to investigate rather than assume fixed

In `qv_mobile_controls.gd`, each action Button connects `button_down/up` to `Input.action_press/release` **and** `_input(InputEventScreenTouch)` handles the same touch by checking button rectangles. Test for double delivery, premature release during overlapping fingers, and dragging off a button. `_touch_active_actions` is a boolean keyed by action, not a per-pointer ownership counter. Joystick uses a single `drag_touch_index`, and mouse/touch events may overlap under emulation. Do not call this a reproduced failure until demonstrated.

## 1. Actual game implementation tasks (P0/P1)

1. **Mobile touch reliability (highest priority).** Reproduce genuine multi-touch combinations (hold movement+attack, move+jump, guard+dash as allowed) in a rendered window using Godot touch event injection. Verify individual finger release cannot cancel another finger's held action. Verify press outside button, slide onto/off button, lost focus, UI toggle OFF, scene transition, and second campaign start correctly clear virtual actions. If flaws reproduce, implement **single-owner input routing / per-finger action ownership** and a coherent event handling path without duplicate Button + `_input` press pairs. Preserve hardware keyboard/gamepad action state.
2. **Touch layout + gameplay legibility.** Inspect actual 1280x720 and 1024x720 frames plus a small representative 16:9 landscape viewport; measure control rectangle bounds, hitboxes and overlap with HUD/boss cues. Fix actual clipping or occlusion via safe responsive placement, not arbitrary numeric score claims. If no issue found, do not create cosmetic churn.
3. **First-play learnability.** Evaluate whether Stage 1 communicates basic Move, Jump, Attack, Guard/Parry, Dash and the touch pad toggle. Implement a small, dismissible, non-blocking playable onboarding hint **only if actual discoverability is weak**, avoiding heavy tutorials or interrupting combat. Make sure hints disappear after initial play and do not obscure threat warnings.
4. **Combat control semantics.** Verify whether 160ms buffered dash and single-use air dash behave reasonably around landing/hit-stun, guard, death/retry and stage transition. Fix only observed control bugs; do not cheat, change enemy HP, or change invulnerability duration merely to pass tests.
