## 2. Checkpoint B — actual playable audio implementation (P0/P1)

Deliver actual GDScript/game asset changes implementing a **small reusable event-driven combat SFX layer** rather than hundreds of repeated AudioStreamPlayer objects. Requirements:
- Distinct attack swing / hit impact / guard block / just-parry / dash feedback, event-triggered from **actual combat callbacks**, not periodically from `_process`. At least 4 of these 5 events must have observable different audible treatment.
- At least two **boss-specific cues** across Stage3 ranged tell, Stage4 heavy slam/fissure, Stage5 blink/storm, selected from actual player-facing gaps. Telegraph plays before or at true windup; not after damage. Boss phases may use a short one-shot accent.
- Stage clear / final victory sound or stinger for reward if missing; protect exactly-once playback and stop/release players safely across stage restart/title.
- Set sensible gain/headroom, avoid overlapping loud bursts via throttling or voice count cap, respect mute/volume settings (existing if present), no clipping, no restart residual audio and no spurious audio during disabled input/paused flow.
- Preserve Stage1-5 HP, battle timing, invulnerability, Option C Z0, previous responsive touch UI, onboarding and victory loop. Do not change player damage numbers or enemy difficulty just for SFX proof.
- If no recorded human listening is available, explicitly mark `SUBJECTIVE_LISTENING_NOT_VERIFIED` but still implement real playable audio with runtime traces.

Checkpoint B **must** commit meaningful actual game source and audio assets before writing ceremonial final reports.
