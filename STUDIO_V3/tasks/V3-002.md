### Adapter contract
- `probe()`: check actual capability and account authentication, no secrets.
- `dispatch(task_id, role, prompt, worktree, timeout)`: returns invocation ID, provider, actual agent/session ID or conversation ID, timestamps, output artifact paths, exit code, provider status and error.
- `observe()`: read updates or terminal status.
- `cancel()`: stop safely; record canceled state.
- `MockAdapter`: deterministic fixtures used only in tests, clearly marked `SIMULATED`.

Prefer `agy -p ... --agent <verified-agent-name> --output-format json --print-timeout <duration>` where local version supports it. For multi-turn use official `--input-format stream-json --output-format stream-json` with one result event per turn and proper process shutdown.

**No use of `--dangerously-skip-permissions`.** Restrict file writes and shell commands to scoped, reversible operations. Capture every permission denial. Never commit credentials or unfiltered tool transcripts containing secrets.

### State and safety
- Extend or replace `STUDIO_V3/workflow.py` while preserving its guarded transitions; do NOT silently bypass reviewer rules.
- Use SQLite transactions (preferred for local Windows runner) or an equivalent tested atomic lock mechanism; `queue.json` can be an export snapshot, not the concurrent source of truth.
- Each job has immutable task ID, revision SHA, role, owner, reviewers, iteration and evidence manifest.
- Log events as append-only JSONL; record `created_at`, `task_id`, `parent_run_id`, `agent_id`, provider, `workspace`, `branch`, `commit_sha`, `evidence_paths`, result and review verdict. Mask secrets and private data.
- Only one writable agent per branch/path set; parallel agents get isolated Git worktrees or read-only access. No unattended merges, force-push, broad deletes or changed permissions.
- Do not execute the next batch when the current task is `BLOCKED`; do not accidentally run `V3-003` before both V3-001 and V3-002 are APPROVED.
- Kill or interrupt runaway jobs with a configurable timeout. Bounded retries (max 2 on transient transport errors) and bounded improvement cycles (default 3 per execution), persisting unresolved issues as `FIX_REQUIRED`. The agent may not repeatedly report success without producing new evidence.

## 5. Independent review and mandatory loop

Real work transitions:
```
READY -> IN_PROGRESS -> IMPLEMENTATION_COMPLETE -> IN_REVIEW
                                            |
                                            +-- reviewer FIX_REQUIRED
                                                        |
                                                        v
                                                   IN_PROGRESS (next cycle)
                                            |
                                            +-- QA PASS + Director PASS -> APPROVED
```

The implementing agent must submit an actual Git diff/commit, test logs and relevant render evidence. The reviewers must be **distinct real invocations**, not the same AI generating a "QA PASS" section in its own response. If independence is not technically established, report `INDEPENDENCE_NOT_VERIFIED` and do not approve.

Issue format: unique ID, owner, priority P0/P1/P2/P3, reproduction, expected/actual, source revision, evidence references, precise fix request and retest. P0/P1 unresolved blocks milestone.

Only independent QA + Director PASS can transition to APPROVED; a model's JSON `status:"SUCCESS"` means that the *agent invocation completed*, not that the task passed quality gates.

## 6. Proof of operation — must run

### A. Deterministic fake-provider integration tests (can run without Antigravity)
Create an isolated `STUDIO_V3/tests/fixtures/` sandbox and verify:
1. Dispatch READY task -> owner-specific invocation event.
2. Owner submits evidence -> IN_REVIEW.
3. Reviewer 1 rejects -> issue created -> FIX_REQUIRED.
4. Producer reassigns -> new iteration -> worker fixes -> fresh evidence.
5. Reviewer 1 PASS but reviewer 2 missing -> still IN_REVIEW.
6. Both independent reviewers PASS -> APPROVED.
7. Owner attempts own approval -> rejected.
8. Evidence path missing, invalid SHA, stale evidence -> rejected.
9. Permission denial, malformed agent JSON, non-zero exit, timeout, cancellation -> no approval.
10. Crash/restart/repeated event -> idempotent queue, no duplicate job/issue, no corrupted state.
11. Two agents attempting concurrent writes to same branch -> rejected/serialized.
12. Pending V3-001/002 dependencies block V3-003, even if a worker writes APPROVED text.

### B. Real Antigravity smoke proof (required for V3-002 approval)
- Run ONE read-only or sandbox-scoped Producer/Client dispatch with the actual provider.
- Run ONE separate QA reviewer invocation; capture different conversation IDs/process invocations.
- Run a **rejection -> remediation -> independent re-review** test on a throwaway fixture (not game code).
- Save provider response envelope, sanitized stderr, command arguments, timestamps, working directory, SHA, review outcomes and status snapshots.
- Confirm custom agents appear in provider discovery (`agy agents` or App agent management), not merely in repo files.
- An agent's assertion `PASS` without external evidence MUST be rejected.

If real CLI is not installed or provider credentials/permissions are missing, tests may pass under mock **but report `INTEGRATION BLOCKED / LIVE NOT VERIFIED`**, not V3-002 APPROVED.
