1. Inspect zip entries in the **real** APK and sort uncompressed/compressed sizes by top directories, file extensions and 20 largest files (no giant binary dump). Check bundled duplicated assets, imported textures and audio, 2 ABIs, unused stages/assets and `export_filter=all_resources` trade-offs. Identify why 542,751,493 bytes, using measured accounting; if most space is necessary for all five stages, document it.
2. Prefer **low-risk** optimizations first: packaging-only changes, unused resource exclusions validated by dependency graph, optional 32-bit ABI exclusion only when the user's target device class is known and preserve supported target coverage in evidence. Re-export and compare **actual byte delta** plus APK signature and 5-stage desktop gameplay regressions; hardware regressions if available.

4. Do not upload APK to public repo or external file host without authorization; if the build artifact is ignored/unavailable remotely, clearly give its **local Windows path**. GitHub commit should contain configs, scripts and text evidence only.
