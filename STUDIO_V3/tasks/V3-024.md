## 1. Deliver a genuine **four-direction character animation** asset pipeline

**Scope / minimum real runtime art:**
- **Hero**: facing screen-left (X-), screen-right (X+), facing away into scene (Z-), facing toward camera (Z+) with distinct actual silhouettes, visible weapon/arm/leg orientation—not merely mirroring or rotating one side-view sprite. Create usable **idle**, **locomotion**, **attack 3-stage combo** in all four directions; **guard/parry, jump/landing, dash/hurt** should at least have consistent directional facing/pivots at action start/end, with relevant transitions; report missing states explicitly instead of fake-complete.
- **Melee grunt**: at minimum true front/back/left/right idle, move, readable windup/strike/recovery. Existing idle/walk/attack 3x2 image alone is insufficient for four-way coverage.
- **Heavy shield knight**: shield/arm poses visible in all four directions for raised guard, bash tell/active/recovery, walking. Use the existing textured heater shield from V3-022 and keep prop physically attached and occlusion-consistent; don't accidentally display an impossible side billboard torso with forward-facing 3D shield.
- **Ranged crossbowman**: four-direction idle/aim/fire/recoil, aligned bolt spawn/muzzle. Prior wizard/projectile freeze regression must remain fixed.
- **Boss**: four-direction readable stance/locomotion plus distinct tell/active/recovery poses for existing three patterns, preserving shield and victory kneeling. If too much for one milestone, prioritize hero + one grunt and submit honest `PARTIAL`; do not claim all classes done via VFX or rotations.

**Assets / production constraints:**
- First audit available `CLIENT/Game/assets/` sprites, sheets, existing tools and licensed local resources. Reuse real assets where credible. If creating new art with available local image-generation/Blender/2D tools, output actual PNG sprite/atlas files under version-controlled `res://assets/` with a consistent look, transparency, canvas size, character scale, feet pivot, weapon hand/impact origin. **Do not submit only prompts, descriptions, concept art, or code-generated colored stick-figure proxies.** Source assets + metadata provenance must be documented. Don't download copyrighted third-party IP or share model/font files.
- An image-generation workflow can introduce inconsistent identity across frames. Solve continuity through reference-sheet consistency checks, character colors/armor/sword/shield, silhouettes, frame to frame alignment; reject bad frames. Favor a few polished directional animations over dozens of obviously mismatched placeholders.
- Decide explicit angle mapping to X/Z: for diagonals, choose 4-way dominant vector or implement 8-way only when distinct authored assets exist; don't secretly call four side-flipped frames 8-direction art.
- Atlas/texture budget must consider 8GB GPU development but Android target eventually; avoid huge 780x780 x many separate draw calls. Provide measured import sizes and atlas packing plan appropriate to Compatibility renderer.
- Introduce an animation resource manifest `res://assets/.../directional_animation_manifest.json` or `.tres` describing character/state/facing/frame counts, fps, anchors, hit/active frames and optional source. Add a small validator for missing files, inconsistent atlas cells/alpha/pivot/feet bounds. The actual Godot runtime must look up this manifest or equivalent typed resource; do not leave new assets unused.
