## 0. Decision: User's Desired Art Direction Overrides Previous V3-024 Specification

User explicitly rejects **front-facing/back-facing (+Z/-Z) sprites** as uglier and unnatural. This is a **design decision**, not a request to perfect/redo four-direction sprites. Restore classic **side-facing belt-scroll style**: characters visually face **left/right only**; walking up/down the stage Z-depth lane retains the same sideways silhouette and moves it spatially up/down in the world, with feet/shadows anchored. This is intended. No floor arrows needed. DO NOT reinterpret as 4-direction art task and do not replace gameplay Z navigation with only X movement.

User also reports the boss repeatedly corners the player so movement is impossible, and boss fight can end with character(s) leaving camera view. A previous self-awarded 9.21/10 visual review failed to catch these; quality gate must be marked pending until actual user-facing video proves correction.

## 2. Priority 1: Side-Facing-Only Visual Policy; Keep True 2.5D Controls

Verified `side_qv_player.gd` V3-024 `_process_movement` lines ~526-533 switches from SIDE to `FRONT_SOUTH`/`BACK_NORTH` on Z movement; `_update_character_animation` lines ~1492-1509 swaps to `TexFrontAttack`/`TexBackAttack`. Remove those runtime-facing transitions: X- => flip_h true, X+ => flip_h false, moving Z only => retain **last X-facing**; never change to front/back sprite solely because Z is moved. Use existing side sprites `TexIdle/Run/Attack/Guard/Dodge/Jump/Hurt/Death`, maintain existing pivots. Left/right attack when X aiming, depth-target Z hitbox and attack vector may still be oriented in 3D when needed, but physical strike visuals must be reasonable in side view. No huge floor arrows or rotated torso to fake it.
- **Player (`side_qv_player.gd`)**:
  - Maintain `facing_dir_x` (1.0 = Right, -1.0 = Left).
  - When moving along Z without horizontal input, preserve previous `facing_dir_x`.
  - In `_update_character_animation()`, set `sprite_3d.flip_h = (facing_dir_x < 0.0)`.
  - Always play high-fidelity side-view animations: `TexIdle`, `TexRun`, `TexAttack`, `TexGuard`, `TexDodge`, `TexJump`, `TexHurt`, `TexDeath`.
  - Hide distracting floor direction arrows/rings (`hero_locator_ring_3d.visible = false`), relying on clean character silhouettes and ground contact shadow.
- **Melee Grunts (`side_qv_enemy.gd`)**:
  - Always use `MeleeTexture` (3x2), facing toward player with `flip_h = (diff.x < 0.0)`.
- **Boss Commander (`side_qv_boss.gd`)**:
  - Always use 4x3 side-view sheets (`BossTextureNormal`, `BossTextureDefense`), with `flip_h = (facing_dir_x < 0.0)`.
- Attack lock/facing stable during Z side-step; diagonal input chooses explicit X sign, Z-only motion keeps X sign. Preserve collision, shield front/back semantics and Z hit detection. Avoid canceling a valid attack solely because visual sprite stays side-on.
- V3-024 newly generated directional PNGs remain in Git history for provenance, but **their live runtime bindings are disconnected**.
- Deterministic directional validation lab executed at 1280x720 (`CLIENT/Game/tests/animation/direction_animation_lab.gd`), capturing side-facing Z-traversal strips (`captures/01_hero_4way_idle.png` ~ `05_boss_4way_combat.png`).

## 3. Priority 2: Boss Arena Duel Containment & Anti-Corner Trapping

Reproduce with actual V3-024 stage1 fight **without HP/position cheats in natural run**. Verified source `side_qv_stage_1.gd` boss sanctuary places `Gate_Boss_Rear` at x=68, boss x=78, and camera center clamps to x=74..78, while player may move x within large global stage bounds -12..88. Boss charge + shield/knockback can shove actor into arena left/right edges or leave player pinned against barrier.
- **Sanctuary Arena Bounds Clamping**:
  - Configure sanctuary bounds: `arena_min_x = 69.2`, `arena_max_x = 85.8`, `arena_min_z = -2.6`, `arena_max_z = 2.6`.
  - Clamp position after physics step: `_clamp_arena_bounds()`.
- **Wall Crash Interruption & Rebound**:
  - In `Pattern.CHARGE_ACTIVE`, detect wall collision (`is_on_wall()` or boundary proximity).
  - Immediately abort charge upon wall contact, trigger screen shake (`camera.add_trauma(0.25)`), spark VFX, and rebound velocity (3.2 m/s away from wall towards arena center).
  - Transition immediately into 0.65s recovery, rewarding the player for baiting wall collisions.
- **Anti-Corner Standoff & Z-Lane Yield**:
  - In `Pattern.CHASE`, if player is within 1.8m of arena walls, increase standoff distance to 2.35m.
  - If boss shares player's Z corridor, bias boss Z movement to yield a clear escape lane.
  - If boss itself is near a wall, step towards arena center ($X \approx 78.0$).
  - In `_prevent_player_pushing()`, actively repel the boss if the player is cornered against a boundary wall.
